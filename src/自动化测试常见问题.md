# 自动化测试常见问题

## progress 跨端测试排查

本次排查覆盖属性更新、控件查询和动画事件。属性区由 `component-template` 渲染，滑块、开关和组合框由其中的 `form-item` 渲染。[测试用例](pages/component/progress/progress.test.js) · [页面示例](pages/component/progress/progress.uvue) · [属性模板](components/component-template/component-template.uvue)

### 属性更新与动画事件

- 属性更新用例通过 `page.callMethod('updateProgressProperty', { name, value })` 调用页面暴露的更新方法，检查共享预览的属性和默认用法示例的进度。该路径覆盖页面更新和数据绑定，滑块拖动及开关点击需要单独的交互用例覆盖。
- 移除 `element.trigger('activeend', ...)` 后，测试点击 `#progress-event-activeend-run` 按钮启动动画。在支持 `activeend` 的平台，检查事件日志中的 `curPercent=70`。预览与滑块同步用例单独检查两者均更新到 `70`，并确认默认用法示例的进度仍是 `0`。

### 小程序控件查询与取值

页面级 `page.$('#progress-properties')` 和 `page.$('#progress-percent')` 在小程序上可能返回 `null`，因为目标节点在自定义组件内部。测试通过 `#progress-template` 定位模板组件，用 `.progress-percent-form-item` 等按属性名生成的 class 定位表单项。表单项使用 class 作为查询标记，可避免虚拟宿主的 ID 继承覆盖组合框原有的 ID。

| 平台 | 控件定位与取值 |
| --- | --- |
| 微信小程序 | 虚拟宿主无法通过 `page.$()` 定位时，在 `program.evaluate()` 中使用 `selectComponent()` 获取模板组件和表单项。原生节点通过 `wx.createSelectorQuery().in(scope)` 查询，滑块用 `.fields({ properties: ['value'] })` 读取值。组合框对应的自定义组件按 ID 用 `selectComponent()` 查询。 |
| 支付宝小程序 | 先用 `page.$('#progress-template')` 获取模板组件，再用 `element.$()` 逐层进入表单项并定位控件。滑块通过 `property('value')` 读取绑定值。 |

小程序原生 `progress` 的 `active=false` 通过 `attribute('active')` 读取时可能得到 `null`。用 `property('active')` 读取布尔值，`show-info` 则用 `property('showInfo')`。检查动画同步时，为 `page.waitFor()` 显式设置 5 秒超时，并对滑块查询结果做非空断言，便于区分控件缺失和数值未更新。
