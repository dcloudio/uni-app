# 暗黑模式适配规范

本文约束 `hello-uni-app-x` 中页面、公共组件和示例组件的暗黑模式适配。目标是在 Web、App 和小程序端保持内容可读，同时不改变示例原本要验证的属性、颜色和原生组件行为。

## 1. 基本原则

1. 使用 `@media (prefers-color-scheme: dark)` 响应系统主题，不在页面中维护重复的暗黑状态。
2. 普通界面的颜色使用语义变量，不根据当前页面效果临时选择一个固定色值。
3. 当前 dev、alpha、master 均使用 Vapor，公共主题变量统一定义在 `page` 选择器中，不再使用 `.uni-theme-root` 建立作用域。
4. 文字颜色应直接应用到 `text`、`input`、`textarea` 或其他实际绘制文字的控件，不能只设置父级 `view` 的 `color`。
5. 暗黑模式适配不能改变示例的测试目的。固定颜色、透明度、层叠和滤镜等被测值应保留，只修复其外围说明和必要的前景对比度。
6. 亮色和暗色必须同时验收。修复暗色时不能造成亮色回归。

本文中的“必须”表示提交前必须满足；“建议”表示无特殊原因应采用。

## 2. 主题作用域

公共变量定义在 `common/uni.css`。

- 所有 Vapor 平台通过 `page` 获得公共变量。
- `page` 同时设置页面级 `background-color: var(--background-color)`，用于补充 `theme.json` 在微信小程序上不响应暗黑主题的问题。
- 页面根节点是 `scroll-view`、`list-view` 等容器时，不需要再添加主题类；页面背景由 `page` 负责。
- 组件内部使用公共变量时，直接读取 `page` 提供的 CSS 变量，并在自身文本、面板等实际节点上显式设置颜色。
- 多窗口节点若不在 `page` 作用域内，应使用已有的窗口业务类补充变量或背景，不得重新引入 `.uni-theme-root`。
- 依赖 `pages.json` 或 `setPageStyle` 设置 `backgroundColorContent` 的示例页面，必须在页面样式中将 `page` 背景设为 `transparent`，避免公共 CSS 覆盖原生背景和截图基线；若某平台未配置原生背景，则使用条件编译保留公共 `page` 背景。

推荐写法：

```html
<template>
  <scroll-view class="page-root">
    <text class="page-title">标题</text>
  </scroll-view>
</template>

<style>
.page-title {
  color: var(--text-color, #333333);
}
</style>
```

`var()` 的 fallback 必须是该变量的亮色默认值，确保不支持变量或作用域缺失时仍能正常显示。

## 3. 公共变量用途

| 变量 | 用途 | 不应用于 |
| --- | --- | --- |
| `--background-color` | 页面底色、窗口底色、大面积次级背景 | 列表项、弹窗内容等前景表面 |
| `--list-background-color` | 列表、卡片、弹窗内容、输入区域等前景表面 | 整页背景 |
| `--text-color` | 标题、正文、label、值文本和输入内容等主要文字 | 固定彩色背景上的文字、弱化说明文字 |
| `--active-color` | 次要文字、弱化说明、未选中状态的前景色 | 主要正文和禁用态背景 |
| `--active-background-color` | 按压态、选中态、弱化块和交互反馈背景 | 页面主背景 |
| `--arrow-color` | 箭头、chevron 等导航指示图形 | 普通正文 |
| `--border-color` | 分割线、卡片边框、输入框边框 | 强调色或错误提示 |
| `--tips-color` | `uni-tips` 的前景文字 | 普通正文 |
| `--tips-background-color` | `uni-tips` 的背景 | 普通页面背景 |
| `--tips-border-color` | `uni-tips` 的强调边框 | 通用分割线 |

### 3.1 局部变量

公共变量无法表达组件的独立语义时，可以定义局部变量，但必须满足以下要求：

1. 变量名带组件或页面前缀，例如 `--dialog-placeholder-color`、`--page-intro-title-color`。
2. 在组件普通样式中定义亮色值，在同一组件的暗色媒体查询中覆盖暗色值。
3. 仅在两个及以上规则需要共享同一语义值时增加变量；单个规则可以直接在亮色和暗色块中分别声明。
4. 可复用语义不得在多个页面各自发明不同变量名，应先评估是否应提升到 `common/uni.css`。

示例：

```css
.dialog-field {
  --dialog-placeholder-color: #808080;
  background-color: #ffffff;
  color: #333333;
}

.dialog-placeholder {
  color: var(--dialog-placeholder-color, #808080);
}

@media (prefers-color-scheme: dark) {
  .dialog-field {
    --dialog-placeholder-color: #b8b8b8;
    background-color: #3b3b3b;
    color: #ffffff;
  }
}
```

### 3.2 新增公共变量

新增公共变量前必须确认：

- 至少存在两个独立页面或公共组件需要相同语义。
- 名称描述用途而不是色值，例如使用 `--placeholder-color`，不要使用 `--gray-8`。
- 同时提供亮色值、暗色值和使用处的亮色 fallback。
- 所有 Vapor 平台的 `page` 中保持同名、同义；组件局部变量不应复制公共变量块。

## 4. 控件适配规则

### 4.1 文本

- 标题、正文、label和值文本必须在自身 class 上设置 `color`。
- 公共样式优先使用 `.uni-title-text`、`.uni-info`、`.uni-label` 等已有语义 class。
- 不要为了暗黑模式统一包装原生 `text`。`pages/component/text/**` 等原生组件示例必须保留原生结构。
- 富文本外围说明使用主题色；富文本内部作为测试数据的颜色按例外规则处理。

### 4.2 输入控件

- `input` 和 `textarea` 必须同时检查文字、背景、边框和 placeholder。
- placeholder 使用 `placeholder-class`，并为该 class 提供亮色和暗色颜色。
- 禁用态、只读态、聚焦态和有值状态不能只验收其中一种。

### 4.3 面板、列表和弹层

- 页面背景使用 `--background-color`，内容表面使用 `--list-background-color`。
- 面板内文字必须落到实际文字控件，不能依靠面板的 `color` 继承。
- 弹层必须同时检查遮罩、内容表面、标题、正文、按钮、输入控件和关闭入口。
- 边框和分割线使用 `--border-color`，不能在暗色表面继续使用仅适合白底的浅灰线。

### 4.4 原生控件

- `radio`、`checkbox`、`switch`、`slider` 等优先使用平台默认的主题适配。
- CSS 能表达的样式不得通过 UTS/JavaScript 维护 `isDarkMode` 分支。
- 只有控件属性必须接收具体颜色、且平台默认样式不能满足可读性时，才允许在运行时读取主题并设置属性；同时必须监听主题切换并覆盖所有目标平台。
- 不修改平台控件内部不可控的文字或刻度样式。若影响验收，应记录平台、系统版本和具体控件状态。

## 5. 选择器规则

面向 App-UVue 的样式必须使用单一 class 选择器。逗号分组可以使用，但分组中的每一项都必须是单一 class。

允许：

```css
.dialog-title,
.dialog-content {
  color: var(--text-color, #333333);
}
```

禁止在跨端样式中使用：

```css
text { color: #ffffff; }             /* 标签选择器 */
#title { color: #ffffff; }           /* ID 选择器 */
.panel text { color: #ffffff; }      /* 后代选择器 */
.panel > .title { color: #ffffff; }  /* 子选择器 */
.panel.title { color: #ffffff; }     /* 复合选择器 */
:deep(.title) { color: #ffffff; }    /* 穿透选择器 */
```

`page` 是当前 Vapor 跨平台主题入口，可以用于公共变量和页面背景。除 `page` 外，仍应遵守简单 class 选择器规则；`:deep()` 仅用于确有需要的 Web 组件覆盖。

## 6. 禁止写法

以下写法禁止用于普通界面：

1. 在页面正文、标题、面板或输入区直接写只适合亮色背景的 `#333`、`#666`、`#888`、`#999`、`#fff` 等固定颜色。
2. 只给父 `view` 设置 `color`，期待 App 端的子 `text`、`input` 或 `textarea` 自动继承。
3. 暗色模式只改文字，不检查对应背景、边框、placeholder 和交互状态。
4. 使用 `isDarkMode`、`darkModeClass` 等页面状态复制 CSS 媒体查询已经能够完成的工作。
5. 使用全局标签选择器、通配符或无边界的 `:deep()` 批量覆盖页面。
6. 为解决暗色问题改变被测 CSS 属性、测试数据颜色或原生组件结构。
7. 为普通文字创建 `theme-text`、`theme-view` 等只转发属性和样式的通用组件。
8. 使用 `!important` 掩盖层叠问题。平台组件确实无法覆盖时，仅可在条件编译块中使用，并写明原因。
9. 只验证编译通过或只验证首屏，不检查需要展开、切换、输入或弹出的状态。

## 7. 例外规则

### 7.1 CSS 属性和颜色示例

cyan、aqua、red、green 等背景可能是示例结果的一部分，暗色模式下不得为了统一视觉而替换背景。背景固定时，应为其中的说明文字增加独立 class，并选择在该固定背景上清晰可读的前景色。

空 `view`、空 `text`、透明度、层叠、尺寸等测试节点没有可见文字时，不要求额外增加前景色。

### 7.2 富文本和编辑器测试数据

用于验证节点颜色、内联样式、HTML 或富文本解析结果的内容保持原值。仅适配测试画布之外的页面标题、说明、操作区和容器背景。

若测试目标明确要求白色画布，暗色模式仍保留白色画布，并确保外围说明与页面背景可区分。

### 7.3 图片、视频和 Canvas

媒体内容本身不进行色相、亮度或滤镜处理。只适配媒体外围的标题、说明、占位背景、边框和操作控件。

### 7.4 平台原生和第三方内容

系统弹窗、原生控件内部、WebView、地图、广告和第三方组件无法由当前页面控制的区域可以例外。必须保证页面自身提供的说明和操作入口可读，并在验收记录中注明未覆盖区域。

### 7.5 自动化截图不稳定页面

动态时间、网络数据、摄像头、视频和随机内容不适合直接作为固定基准图。应固定数据或等待状态稳定后进行人工截图验收；无法稳定时，在验收记录中写明原因和人工检查结果。

任何例外都不能用于普通业务说明文字。新增例外必须在代码附近写明被测目标，或在提交/验收说明中列出页面、元素和原因。

## 8. 截图验收范围

### 8.1 通用要求

每张暗色截图必须有同平台、同尺寸、同数据、同交互状态的亮色对照。截图必须包含发生变化的完整区域，不能只截取一个文字像素点或避开上下文背景。

截图检查项：

- 页面和滚动区域不存在非预期白底或黑块。
- 标题、正文、说明、label、值文本、placeholder 和禁用文字清晰可读。
- 列表、面板、弹层、输入区之间的背景层级可辨认。
- 边框、分割线、箭头和未选中 tab 可辨认。
- 固定彩色背景上的文字仍有足够对比度。
- 图片、富文本、Canvas 和 CSS 测试结果没有因主题适配而改变测试语义。
- 页面切换主题后无需重新进入即可正确刷新；平台不支持动态切换时，分别冷启动验证。

普通文字与背景的对比度建议不低于 `4.5:1`；大号文字和非文字 UI 边界建议不低于 `3:1`。测试数据颜色属于例外，但外围说明仍需满足该建议。

### 8.2 按改动范围确定平台

| 改动范围 | 必须截图的平台和页面 |
| --- | --- |
| 页面局部样式 | Web 亮色/暗色；该页面实际支持的 App 或小程序端至少验证一个。包含平台条件代码时必须验证对应平台 |
| 公共组件 | Web、Harmony、微信小程序各选至少一个真实调用页面，均提供亮色/暗色截图；组件的不同状态必须覆盖 |
| `common/uni.css` 公共变量或公共 class | Web、Harmony、微信小程序均验证；至少覆盖列表页、表单页、弹层页、CSS 示例页和富文本/媒体页各一个 |
| 原生控件样式 | 必须在受影响的真实设备或模拟器平台截图，Web 截图不能替代 |
| 平台专用代码 | 只要求对应平台，但必须同时提供亮色/暗色对照 |

Harmony 和微信小程序无法完成自动截图时，可以使用真机或开发者工具人工截图，但不能仅用 Web 结果推断通过。

### 8.3 必须覆盖的交互状态

页面存在下列状态时，除默认首屏外还必须截图：

- dialog、popup、page-container：打开后的完整弹层。
- input、textarea：空值 placeholder、有值状态；修改了聚焦样式时增加聚焦状态。
- tab、swiper：每种视觉样式至少一个未选中项和一个选中项。
- 折叠面板、裁剪参数、更多设置：展开状态。
- 长页面：首屏以及实际修改区域，修改区域不在首屏时必须滚动后截图。
- 动态主题：主题切换后的页面状态，确认没有残留旧主题颜色。

### 8.4 基准图和验收记录

- 已加入 `pages/pages.test.js` 的页面，按 `自动化测试说明.md` 更新或删除受影响的旧基准图后重新生成。
- 不适合自动截图的页面使用人工截图，并记录平台、设备或模拟器、系统版本、主题和页面状态。
- 截图默认作为本地或评审证据，不要求提交到仓库；发布流程、Issue 或 PR 有明确要求时按其目录和命名规则提交。
- 构建成功不能替代截图验收，截图通过也不能替代 Web、Harmony 和微信小程序的编译检查。

## 9. 提交前检查清单

- [ ] 页面或组件根节点已建立正确的主题作用域。
- [ ] 实际文字控件使用语义变量或经过说明的固定前景色。
- [ ] 背景、边框、placeholder、禁用态和交互态已检查。
- [ ] 没有跨端不支持的选择器和无边界的全局覆盖。
- [ ] 没有改变示例的被测属性、测试数据或原生组件结构。
- [ ] 所有例外均有明确的页面、元素和原因。
- [ ] 按改动范围完成亮色/暗色截图，并覆盖必要交互状态。
- [ ] Web、Harmony、微信小程序完成与改动范围相匹配的编译验证。
- [ ] `git diff --check` 通过，且未误改 `uni_modules` 或生成产物。
